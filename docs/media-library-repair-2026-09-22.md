# 媒体库同步修复（2026-09-22）

本次在现有本地版本上修复，保留原有 `extension/background.js` 工作标签页改动。已检查 upstream/main（d7977fd），未整体合并上游的其他功能变更。

## 根因与修复

- 项目列表 API 返回顶层 `title`，前端仍只读取旧的 `projectInfo.projectTitle`，因此显示 UUID 前八位。现在兼容两种字段。
- 新版 Flow `Zzl0ze` 的完整媒体数据位于 `payload[2]`；旧适配只读 workflow 身份信息并复用本地提示词，遗漏云端原文和译文。
- 同步只取 150 条，列表又按 UUID 排序；25 秒超时会在大型项目响应返回前取消请求。现在同步读取完整集合，项目超时为 180 秒，并明确返回失败信息。
- 从媒体记录提取原文、译文、创建时间、比例和媒体类型。图片标题不充当云端原始提示词，未知模型也不再标为用户上传。
- 数据库 upsert 不用空字符串覆盖已有内容；云端创建时间可纠正旧的本地时间。
- Flow 的 `lh3.googleusercontent.com/asb/` 地址在无登录的后台下载中会返回 HTTP 200 登录页。旧实现把任意非空响应当成图片，产生虚假缓存。现在验证媒体签名，拒绝 HTML/JSON，自动重新检查并修复旧缓存。
- 恢复迁移中遗漏的 `resolve_media_url(s)`，通过新版媒体 RPC 获取可下载的签名地址。批量地址解析最多 5 个并发。
- 图片与视频分别使用其真实媒体记录，避免把视频海报当成视频本身。
