## Earlier investigation (historical, not current recovery instructions)

Observed: local media-library reads succeed from cache, while Google API returns
401 UNAUTHENTICATED. Extension connectivity and key presence do not prove validity.

Root causes in extension: outgoing proxy requests are recaptured and reset the
stored token age even when unchanged; refresh only reinjects an idempotent script,
which does not make the Flow application renew its login token.

Fix existing behavior: accept captures only from Flow page tabs, do not refresh
the age of identical tokens, reload the existing Flow tab for token refresh, and
invalidate only the exact token rejected by a 401 (preserve a newer in-flight
capture). Request page refresh but never automatically replay the failed paid
generation request. Interactive Google login, if required, remains user-owned.

No tokens or cookies in logs/tests/reports. Validate using mocked Chrome and fetch,
then reload the extension and perform a read-only Google API check. Local cache
availability alone is not successful verification.

Verification: `node tests/extension_mv3_bootstrap.test.cjs` passed cold start,
worker-self-capture rejection, identical-token age preservation, 401 invalidation,
one request only, actual tab reload, and preservation of a newer concurrent key.
Reloaded the installed extension through the existing reload endpoint. Live
authenticated media read currently reports NO_FLOW_KEY; Google Flow project UI
is signed in and cached project media is visible, but a fresh OAuth capture has
not been observed. Do not claim live API recovery until an authenticated Google
API request succeeds. No generation request was replayed or charged by this fix.

Follow-up: user successfully generated two new images in the official Flow UI.
Page traffic observed on reload uses the same-origin
`/_/AiSandboxAngularFrontend/data/batchexecute` route with no Authorization header.
No fresh legacy Google API Bearer key was observed. This is evidence of a frontend
transport compatibility gap, not evidence that the user's Google login failed.
The old FlowKit code only handles aisandbox REST and /api/trpc; adapting the new
RPC requires observing its image-generation request and response contract.
Do not ask for repeated paid generations merely to refresh an old token.

Capture guards now accept opaque Bearer formats only when sent to the exact
aisandbox API host from a trusted Flow origin (including Flow service workers).
Local diagnostic probes have been removed; no header values were recorded.
